# ADR-0004: 조회 레이어 이원화 + 메시지 발송은 외부 채널

- 상태: 승인
- 날짜: 2026-09-01

## 맥락 (조사로 확정된 사실)
- ClassIn 파트너 API의 목록/상세 조회 액션(getCourseList 등)은 실존하지만 공식 문서
  TOC에서 숨겨져 있고 SID별로 활성화가 필요하다. 활성화 전 호출은 errno 102 등으로 거절된다.
- 아웃바운드 메시지 발송 API는 존재하지 않는다 (IM 그룹 자동 생성만, 쓰기 API 없음).
- AI 강의분석 결과는 파트너 API로 제공되지 않는다.
- Data Sub 웹훅은 10초 무한 재시도 + FIFO 헤드오브라인 블로킹이며, 성공 응답 envelope를
  반드시 반환해야 한다.

## 결정
1. **조회 이원화**: 대시보드 데이터 소스는 (a) 웹훅 축적 store(보장된 바닥) + (b)
   `classin/reads.py`의 베스트에포트 조회(활성화 시 가속). 조회 실패는 오류가 아니라
   "미활성" 안내로 강등하고 웹훅 데이터로 동작한다.
2. **웹훅 수신은 무조건 ack**: 원본 JSONL 저장 → `{"error_info":{"errno":1}}` 반환 →
   `_id` 기반 중복 제거 후 파싱/적재. 파싱 실패도 ack (원본은 보존되어 replay 가능).
3. **메시지 발송**: ClassIn 경유 발송 기능을 만들지 않는다. 문구 생성(AI 개인화 or
   템플릿) + 발송 이력 기록을 1급 기능으로 하고, 알림톡 공급자(알리고/솔라피)는
   notify/dispatcher.py의 sender 플러그인으로만 추가한다.
4. **AI 강의 평가**: Rating 웹훅(S2T 점수/코멘트) 누적을 기본 표시로 하고, ClassIn이
   AI 분석 API를 열면 config 주입식으로 연결한다 (화면·모델 변경 없이).

## 결과
- 조회 API 활성화 여부와 무관하게 제품이 동작하고, 활성화는 코드 변경 없이 가치 상승.
- 웹훅 스트림이 한 건의 불량 페이로드로 정지하는 사고(헤드오브라인)를 구조적으로 차단.
