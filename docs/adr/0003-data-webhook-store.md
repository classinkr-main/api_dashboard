# ADR-0003: 데이터 전략 — 실시간 API 조회 + 웹훅 이벤트 축적(SQLite/JSONL)

- 상태: 승인
- 날짜: 2026-09-01

## 맥락
- ClassIn 데이터 중 일부(과제 제출, 수업 후 리포트, 출결 상세)는 조회 API보다 Data Sub(웹훅) 푸시가 주 채널이다.
- 대시보드는 "지금 조회" 지표와 "축적해야 보이는" 지표가 섞여 있다.

## 결정
- **코스/수업/구성원 등 마스터 데이터**: ClassIn API 실시간 조회 + 짧은 TTL 인메모리 캐시.
- **이벤트성 데이터(출결·과제·수업종료·AI 리포트)**: 웹훅 수신 즉시
  1) 원본 JSONL append (감사·재처리용, `data/webhook/YYYY-MM-DD.jsonl`)
  2) 파싱 성공 시 SQLite `events` 테이블에 정규화 적재
- 대시보드 집계는 SQLite에서 수행. 파싱 실패 이벤트도 원본은 보존되므로 스키마 추가 후 replay 가능.

## 결과
- 웹훅을 아직 못 받는 초기에도 API 조회 항목은 동작하고, 축적형 지표는 "수집 대기" 상태로 표기.
- 외부 DB 의존성 없음(단일 볼륨 백업으로 충분).
